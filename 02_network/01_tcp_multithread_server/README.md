# 멀티스레드 TCP 채팅

Linux/Jetson에서 C와 POSIX threads(pthread)로 실행하는 채팅 예제다.
서버는 최대 5명을 받고, 각 연결의 메시지를 보낸 사람을 포함한 모든 접속자에게 전달한다.

## 빌드와 실행

```bash
cd 02_network/01_tcp_multithread_server
make
./build/server
```

다른 터미널을 여러 개 열어 각각 실행한다.

```bash
./build/client
# 다른 장치에서 접속할 때는 서버의 IPv4 주소를 지정한다.
./build/client 192.168.0.10
```

포트는 TCP 8080이다. 기존 00_tcp_echo 서버와 동시에 같은 포트를 사용할 수 없다.
메시지를 입력하고 Enter를 누르면 `[Client 1] 안녕하세요` 형태로 표시된다.
클라이언트는 `/quit` 또는 Ctrl+D, 서버는 Ctrl+C로 종료한다.
클라이언트 번호는 연결 슬롯 번호이며 퇴장 후 재사용된다.

## 스레드와 동기화

- 서버 main: `accept()`로 연결을 받고 슬롯을 배정한 뒤 작업 스레드를 만든다.
- 서버 작업 스레드: 담당 소켓에서 수신하고 완성된 줄을 브로드캐스트한다. 종료 시 소켓과 슬롯을 반환한다. detached 스레드이므로 종료 후 스레드 자원도 자동 회수된다.
- mutex: 접속 목록 변경, 전송, 소켓 닫기를 보호한다. 같은 메시지의 부분 전송이 다른 메시지와 섞이거나, 닫힌 소켓 번호가 재사용되어 잘못 전송되는 것을 막는다.
- 클라이언트: main은 수신과 출력, 송신 스레드는 표준 입력과 전송을 담당한다. 입력 중에도 다른 사람의 메시지를 받을 수 있다.

스레드 인자는 힙에 별도로 할당한다. 반복문 지역 변수의 주소를 그대로 넘겨 다른 연결의 번호를 읽게 되는 문제를 피한다.
5명이 연결된 상태에서는 추가 연결에 안내를 보내고 닫는다. 퇴장한 자리는 다시 연결할 수 있다.

## 통신 규칙과 범위

줄바꿈(`\n`)이 메시지 경계다. 한 줄은 줄바꿈 포함 최대 1024바이트이며 UTF-8 한글은 보통 한 글자에 여러 바이트를 사용한다.
서버는 TCP 수신이 나뉘거나 여러 줄이 한꺼번에 도착해도 줄 단위로 처리한다.
규격을 넘긴 연결은 닫으며, 줄바꿈 없이 연결이 종료된 미완성 줄은 버린다.
클라이언트는 너무 긴 입력을 버리고 알린다. `/quit`은 클라이언트 내부 명령이다.

부분 전송은 반복하고 `EINTR`는 재시도한다. `MSG_NOSIGNAL`로 끊어진 연결에 전송할 때 서버 전체가 SIGPIPE로 종료되는 것을 방지한다.

학습용으로 mutex를 잡은 채 블로킹 전송한다. 소켓 전송 호출에 2초 타임아웃을 설정했지만, 느린 수신자는 다른 연결의 처리도 지연시킬 수 있다. 전체 브로드캐스트의 총 소요 시간을 2초로 제한하는 것은 아니다.
대규모 서비스에는 연결별 송신 큐 등 별도 설계가 필요하다. 서버의 Ctrl+C 종료는 프로세스 즉시 종료이며 진행 중인 메시지 전달을 보장하지 않는다.
